PHP runtime RCE remediation

Prepared fix: PHP 8.4.27, patched version requirements, and session upload-progress hardening.

Status: draft; dependency audit and preview check remain open

The PHP 8.4.27 image built locally, and the PHP integration suite passed. Composer audit still reports a vulnerability in the locked Symfony MIME package. The Vercel Preview check also failed. Production has not been inspected or redeployed, and no production deployment was triggered.

What the CVEs mean

CVE-2026-109618 — out-of-memory corruption. A memory failure can interrupt PHP while request data is only partly initialized. Shutdown may then use invalid state, enabling code execution as the web worker. Upstream demonstrated remote exploitation with Apache mod_php; PHP-FPM remains susceptible under application-dependent conditions, without a complete demonstrated FPM exploit for this advisory. Updating PHP is the complete mitigation. PHP advisory.

CVE-2026-109619 — stale global state. A worker can retain references to memory from a finished request. A later request may use those references after the memory is freed. The session upload-progress path has been validated with FPM when suitable application operations are reachable. Disabling that feature reduces exposure but does not replace the complete PHP patch. PHP advisory.

Both advisories are critical, rated 9.2 by upstream. Patched releases are 8.2.35, 8.3.36, 8.4.27 and 8.5.12. This application uses Nginx and PHP-FPM; using FPM is not sufficient evidence of immunity.

Changes proposed

FileChange
DockerfilePin the application base to php:8.4.27-fpm-bookworm. The official image manifest lists this tag; registry pull and image execution remain unverified.
composer.json / composer.lockRequire ~8.3.36 || ~8.4.27 || ^8.5.12. Refresh only the platform constraint and content hash; package versions remain unchanged.
docker/php.iniDisable session.upload_progress.enabled. Ordinary application sessions and file uploads remain enabled; upload-progress integrations require checking.

The lock hash was computed using Composer's documented source algorithm, cross-checked against the original lock hash. This is a metadata change, not a dependency solver run.

Checks and limits

  • The no-cache Podman build passed. The resulting image reports PHP 8.4.27 in both CLI and FPM. The frontend build also completed as part of the Docker build.
  • Composer validation passed with the existing missing-license warning. Composer platform checks passed on PHP 8.4.27.
  • Composer audit reports medium advisory CVE-2026-45070 for symfony/mime 8.1.6. Version 8.1.10 fixes it. The separate Statamic dependency update tracks that upgrade, so this PR stays in Draft until the audit passes against the updated base.
  • The PHP feature suite passed: 59 tests, 659 assertions. The three Control Panel CV tests create temporary synthetic users and remove them afterward. The test container used a disposable APP_KEY and did not copy the repository's users directory.
  • The CV PDF test failure came from looking for a URL fragment in extracted visible text. PDF viewers store that fragment in the link annotation. The test now checks the annotation and rejects any extra bare profile URL.
  • The Vercel Preview check failed. Its failure cause is not available in the GitHub status, and the preview has not been retried. No production deployment ran.

Deployment and remaining verification

After the separate Symfony security update is merged, rerun Composer audit and the required checks, then diagnose the failed Vercel Preview. Production rollout remains a separate action. Build with fresh image pulls and package layers, then recreate the service so every old worker is replaced. The existing Dockerfile installs Debian packages from current repositories during a fresh build.

composer validate --no-check-publish
composer audit --locked
composer check-platform-reqs --lock
vendor/bin/phpunit --no-coverage

docker compose -f compose.production.yaml build --pull --no-cache portfolio
docker compose -f compose.production.yaml up -d --force-recreate portfolio
docker compose -f compose.production.yaml exec portfolio php -v
docker compose -f compose.production.yaml exec portfolio php-fpm -v
docker compose -f compose.production.yaml exec portfolio sh -lc "php-fpm -i | grep -E '^(PHP Version|session.upload_progress.enabled) =>'"

Check that CLI and FPM both report PHP 8.4.27 and upload-progress tracking is disabled. The filtered FPM command avoids exposing unrelated configuration, including environment values. Verify /up, the homepage, Control Panel login and uploads, CV sessions, PDF export, and content sync. Review worker startup logs for warnings. Do not roll back to a vulnerable PHP image.
