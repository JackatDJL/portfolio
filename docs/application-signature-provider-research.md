# Application signature provider research

Research date: 2026-11-06. Public official sources only. No accounts, contacts, document uploads, signatures or paid API calls. Findings describe published evidence, not tested onboarding or a legal opinion. Prices and terms can change.

## Decision for this application

Proceed with provider-independent external PDF export/import. No researched live QES API is presently established as both contractually accessible and affordable for a private 17-year-old. D-Trust explicitly serves private people through its portal, but its API conditions and minor eligibility remain unconfirmed. Skribble documents a usable API, but its published customer GTC excludes consumers. DSS is reusable software, not an alternative source of qualified certificates or signing entitlement. See the evidence below.

Do not label an imported PDF "QES verified" from a filename, visual signature, provider selection or successful upload. Keep external signing, cryptographic validation and qualification assessment separate. This is an implementation recommendation, not a claim that validation has been implemented.

## D-Trust sign-me

### Offering, access and cost

D-Trust offers eIDAS QES through sign-me. Its product comparison directs organisations to API integration and occasional private users to the portal. The API product describes one-time identification through AusweisIDent, VideoIdent or organisational PoS identification, followed by second-factor approval. It says every QES receives a qualified timestamp. [Product comparison](https://www.d-trust.net/de/loesungen/sign-me), [API product](https://www.d-trust.net/de/loesungen/sign-me-api).

The portal publishes transaction pricing, without monthly fixed costs: 100 coins cost EUR 34.90 including VAT; 500 cost EUR 139.90 including VAT. QES costs 5 coins, AES 2. Registration includes 10 coins; online-ID identification is free, VideoIdent costs 50 coins. Thus the purchased-credit QES equivalents are EUR 1.745 or EUR 1.399 respectively, before unused balances; the initial cash purchase is EUR 34.90 or EUR 139.90. These are portal prices, not API prices. No seat purchase is described for the personal portal. [Official portal pricing](https://www.d-trust.net/de/loesungen/sign-me-portal).

No public exact API tariff, setup fee, minimum commitment/seats, self-service private API eligibility, sandbox admission procedure or current versioned endpoint/schema reference was located in the reviewed official API material. The privacy notice describes interface documentation, sample code and credentials supplied through a service portal, with access details delivered to the customer by encrypted email. This supports a provisioned integration, not anonymous API access. Do not invent a REST version or treat the consumer account as an API contract. [API product](https://www.d-trust.net/de/loesungen/sign-me-api), [privacy notice, VIII.1](https://www.d-trust.net/de/datenschutzerklaerung).

### Age, data and long-term evidence

Minimum signing/account/API age and a route for a 17-year-old, including any required representative consent, are **unconfirmed**. No affirmative minor eligibility rule was located in the reviewed support, Cloud CPS, TSPS or sign-me subscriber agreement. Silence is not permission. Availability of an online ID or its age threshold does not establish capacity to enter the provider contract. [Support](https://www.d-trust.net/de/support/sign-me), [Cloud CPS](https://www1.d-trust.net/internet/files/D-TRUST_Cloud_PKI_CPS.pdf), [TSPS](https://www1.d-trust.net/internet/files/D-TRUST_TSPS.pdf), [subscriber agreement](https://www1.d-trust.net/internet/files/D-TRUST_Subscriber_Agreement_sign-me.pdf).

Portal signing requires full PDF/A upload, with a 10 MB total limit and up to 16 documents. API signing can receive PDF/A or document hashes, so an appropriately implemented local workflow can avoid sending the document itself. Uploaded portal documents are deleted after five days. This does not mean identity/certificate records disappear then. [Support, document formats and security](https://www.d-trust.net/de/support/sign-me).

The privacy notice distinguishes D-Trust's usual processor role from cases where it is controller. It lists identity/VideoIdent evidence, certificate and access data; support recipients include Bundesdruckerei and INCO Spólka z o.o. The support page places uploaded PDFs in the D-Trust data centre security area. A complete API-specific subprocessor list and binding all-data residency commitment were not established; do not infer them from German branding. [Privacy notice, VIII](https://www.d-trust.net/de/datenschutzerklaerung), [support](https://www.d-trust.net/de/support/sign-me).

The repository lists Cloud CPS effective 2026-09-23 and TSPS effective 2026-10-16; downloaded documents identify versions 4.5 and 3.3. Cloud CPS §1.1.1 permits outsourced components/identification while retaining D-Trust responsibility. The subscriber agreement v2.0 requires protection of credentials and permits retention of certificate-application/authentication records. Its general certificate-publication wording differs from support's optional directory-publication description; resolve the applicable consent wording before use. [Repository](https://www.d-trust.net/en/support/repository), [Cloud CPS](https://www1.d-trust.net/internet/files/D-TRUST_Cloud_PKI_CPS.pdf), [TSPS](https://www1.d-trust.net/internet/files/D-TRUST_TSPS.pdf), [agreement](https://www1.d-trust.net/internet/files/D-TRUST_Subscriber_Agreement_sign-me.pdf), [support](https://www.d-trust.net/de/support/sign-me).

The API page promises a qualified timestamp/LTV, but does not specify PAdES Baseline LT or LTA output in the reviewed material. A timestamp alone does not prove embedded revocation evidence or recurring archival timestamp renewal. Exact LT/LTA output and preservation obligations remain **unconfirmed**. [API product](https://www.d-trust.net/de/loesungen/sign-me-api).

## Skribble

### Contract, API and pricing

Skribble's system-user terms v2025.10.31 explicitly say Skribble is not a QTSP. They name Swisscom IT Services Finance S.E. for eIDAS QES and Swisscom Switzerland for ZertES, with PXL identification where used. The QES user also contracts with those providers. EU and Swiss signature regimes must therefore be selected explicitly. [Terms, §§4.3–5.3](https://www.skribble.com/en-eu/terms-of-use/).

**Consumer blocker:** GTC §2.1 offers services exclusively to traders under §14 BGB and expressly excludes consumers under §13. A natural person can be a customer in a business capacity; that is not private consumer API eligibility. Signing an invitation is a separate system-user role and does not grant an API customer account. [GTC, §§1.6–3](https://www.skribble.com/en-eu/gtc/).

Published EU prices exclude VAT: Starter has one user, no subscription, SES EUR 1, AES EUR 3, QES EUR 5. Team displays EUR 23/user/month with EUR 276 billed yearly, 72 AES/QES per user/year; extra QES EUR 4.50. Pro displays EUR 36/user/month with EUR 432 billed yearly, 120 AES/QES per user/year; extra QES EUR 4. Identification is EUR 24.50 once and valid up to five years. Scale is quoted. API integration, key generation and demo API testing appear only in Pro/Scale. Minimum paid seats are not explicitly established; do not assume one Pro seat is purchasable. The pricing page conflicts internally: comparison says up to 20 users, FAQ says up to 50 with 20 recommended. Its GTC still names an "Individual" plan while pricing names "Starter". These discrepancies need resolution in any actual order. [EU pricing](https://www.skribble.com/en-eu/pricing/), [German API entitlement table](https://www.skribble.com/de-de/preise/), [GTC §4.2](https://www.skribble.com/en-eu/gtc/).

The current overview recommends **Sign API v2 for production**; v3 is preview and subject to breaking changes. Validation API is v1. Do not mistake the documentation footer's API v1.8.0 for the signing endpoint major version. Business-profile credentials are required. Demo keys are free and produce signatures without legal weight; production transactions are billed. A 14-day Pro trial does not establish continuing sandbox entitlement for a consumer/minor. [API overview](https://api.docs.skribble.com/introduction), [v2 access](https://api.docs.skribble.com/api/sign-v2/access), [authentication](https://api.docs.skribble.com/authentication), [pricing](https://www.skribble.com/en-eu/pricing/).

### Identity, minors, privacy and PDF handling

QES identification uses an official ID and, depending on the route, selfie/video or in-person verification. Skribble's identification page conflicts with itself by describing selfie video and later calling live video necessary. Its listed partners also vary by page. Treat the actual selected process and its terms as decisive. [Identification](https://www.skribble.com/en-eu/identification/).

No explicit minimum age or confirmed 17-year-old onboarding/consent route was located in the reviewed Skribble terms, Swisscom eIDAS terms dated July 2026 or PXL terms dated July 2026. PXL's IPSPS v1.0, 2025-01-20, describes age-independent accessibility; this is not contractual minor eligibility. PXL also allows transaction partners/QTSPs to impose restrictions. The private customer blocker above remains independently applicable. [Skribble terms](https://www.skribble.com/en-eu/terms-of-use/), [Swisscom terms](https://ras-docs.scapp.swisscom.com/tc/eidas_en.pdf), [PXL terms](https://pxl-vision.com/hubfs/Terms_and_Conditions/PXL_Ident_QES_Terms-of-Use/TermOfUse_PID-QES_EN.pdf), [PXL IPSPS](https://www.pxl-vision.com/en/ipsps).

The documented v2 document API transfers the full PDF as Base64 content or a file URL; no hash-only signing route was established in these docs. DELETE does not necessarily erase immediately, and with multiple participants it initially removes the caller's association. [v2 document API](https://api.docs.skribble.com/api/sign-v2/document).

API hosting endpoints distinguish Switzerland, `api.skribble.com`, from Germany/EU, `api.skribble.de`; use one region consistently. [API overview](https://api.docs.skribble.com/introduction). The DPA v2025.10.31 Annex 2 lists cloudscale/VSHN for Switzerland and IONOS for Germany, alongside cross-border support and processors including SparkPost, HubSpot, Google Mail, Stripe, Chargebee, tyntec, Userpilot and Cloudflare. It separates QTSP/identity providers from subprocessors. The selected contract and process determine applicability. [DPA](https://www.skribble.com/en-eu/dpa/).

**Conflicting scope:** pricing says data is never processed in the US, while the privacy policy explicitly cannot exclude US transfers through HubSpot and identifies US-based services. German document hosting must not be represented as an all-data/no-US guarantee. Swisscom's eIDAS terms §7.1 separately place certificate issuance systems in Switzerland; §7.4 requires QES evidence retention for 30 years under the stated triggers. [Pricing](https://www.skribble.com/en-eu/pricing/), [privacy §§4–5](https://www.skribble.com/en-eu/privacy/), [Swisscom terms](https://ras-docs.scapp.swisscom.com/tc/eidas_en.pdf).

Skribble claims PAdES-LTV for long-term validation. The reviewed API/FAQ evidence does not establish exact Baseline LT/LTA output or a recurring archival-renewal service. Both remain **unconfirmed** until an output contract and validation evidence establish them. [Official FAQ](https://www.skribble.com/en-eu/faqs/).

## EU DSS

The Commission lists **DSS 6.5.1, October 2026**, as latest, a Java library reusable by citizens/businesses under LGPL 2.1. There are no provider seats or per-signature licence fees; hosting, maintenance and external trust services still have costs. DSS is not a QTSP, identity service or source of a personal qualified signing credential. Its availability does not settle minor eligibility with a QTSP. [Official project and release table](https://ec.europa.eu/digital-building-blocks/sites/spaces/DIGITAL/pages/467109107/Digital+Signature+Service+-+DSS).

DSS supports PAdES creation, validation and augmentation to Baseline LT/LTA. LT embeds validation material; LTA protects it with archival timestamps and requires timely renewal. Its signing model separates document preparation, external private-key signing and PDF assembly, including digest signing. Self-hosting can keep PDFs local, but configured QTSP, TSA, OCSP/CRL and trusted-list services still receive requests. A remote DSS REST deployment may receive the full document. There is no automatic all-local privacy guarantee. Test credentials/demo signatures do not become QES merely by using DSS. It is a possible later validation/augmentation component, not a way around QTSP admission. [Official developer documentation, §§4, 10, 15](https://ec.europa.eu/digital-building-blocks/DSS/webapp-demo/doc/dss-documentation.html).

## Integration consequence and unresolved gates

External import is the appropriate first workflow. sign-me portal is the strongest published low-volume private-person option, conditional on confirming the 17-year-old's eligibility; its consumer affordability says nothing about direct API affordability. Skribble is documented technically but its published customer contract is unsuitable for this private use case. DSS can support later local validation without supplying the missing signing contract.

Before any future live integration, establish the applicable minor/representative contract route, API admission and complete price/minimum commitment, versioned API contract, chosen identity method, full-data/subprocessor geography and retention, and exact PAdES LT/LTA output/preservation service. These are open evidence gaps, not instructions to contact providers or create accounts during this task. No live integration or qualification-validation claim is justified by this research alone.
